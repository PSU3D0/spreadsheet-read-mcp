# agent-spreadsheet 0.15.0

0.15 makes the SDK a programmatic object model over two canonical runtimes, exposes the canonical operation surface over plain HTTP on the MCP server process, cuts the WASM bundle by more than half, and adds a native raster renderer so `screenshot_sheet` works everywhere the engine runs, including inside the browser, without LibreOffice.

## Canonical HTTP route

The MCP server's HTTP transport now mounts `/v1` beside `/mcp`:

| Route | Purpose |
|---|---|
| `POST /v1/op/{operation}` | execute one canonical operation with the canonical request JSON; returns the canonical envelope |
| `GET /v1/operations` | live operation list for this runtime |
| `GET /v1/registry` | full registry descriptors |
| `GET /v1/artifacts/{handle}` | bytes for a `artifact:sha256:…` handle |

Canonical error codes map to HTTP status: `INVALID_REQUEST`, `STALE_CURSOR`, `CURSOR_MISMATCH`, and `ROW_EXCEEDS_BUDGET` → 400; `UNKNOWN_OPERATION` and `RESOURCE_NOT_FOUND` → 404; `REVISION_CONFLICT` → 409; `OPERATION_FAILED` → 500; `CAPABILITY_UNAVAILABLE` → 501. Canonical MCP `screenshot_sheet` responses now also carry the PNG as image content. See `docs/architecture/canonical-http-route.md`.

## SDK 0.15 (breaking for 0.14 backend users)

`agent-spreadsheet-sdk` is rewritten in TypeScript and ships CommonJS, ESM, and `.d.ts`. It is a programmatic object model with exactly two runtimes and is not an MCP client:

```js
const { createLocalSpreadsheet, connectSpreadsheetServer } = require("agent-spreadsheet-sdk")
const { createWasmRuntime } = require("agent-spreadsheet-wasm")

const local = createLocalSpreadsheet({ runtime: createWasmRuntime({}) })   // in-process WASM sessions
const server = connectSpreadsheetServer({ baseUrl: "http://127.0.0.1:8079" }) // canonical /v1 route
```

- Operation names and payloads are generated from the canonical registry: a wrong operation name or input shape is a compile error, and a drift test pins the generated types to the registry.
- Workbook, fork, and view objects inject resource identity and tracked revisions; `client.canonical.execute(operation, input)` remains available on every runtime.
- One error hierarchy: `SpreadsheetError`, `CanonicalOperationError`, `CapabilityError`, `TransportError`.
- `renderSheet()` returns `{ png, fidelity, warnings, calculation, width, height, png_level }` on both runtimes. Image bytes cross the adapter boundary (HTTP artifact route or the WASM byte binding); there is no canonical artifact-retrieval operation.
- Worker mode for the local runtime keeps rendering off the main thread. The just-bash adapter is unchanged in shape and gains screenshot output.
- The 0.14 `McpBackend` / `WasmBackend` classes moved to `agent-spreadsheet-sdk/compat` for one compatibility window and are deprecated.
- README examples are executed by the test suite.

## WASM diet and the `agent-spreadsheet-wasm` package

Host-only crates (clap, tokio, tempfile, walkdir, LibreOffice paths, filesystem workspace) are feature-gated out of the wasm32 build, the build uses a dedicated `wasm-release` profile plus `wasm-opt`, and sessions are resident so repeated operations do not re-parse.

| Measure | 0.14 | 0.15 |
|---|---|---|
| bundle, raw | 21.0 MB | 9.2 MB |
| bundle, brotli | 3.37 MB | 2.25 MB |

The bundle ships as the new npm package `agent-spreadsheet-wasm` with a `createWasmRuntime()` loader for Node and browsers, and CI enforces `wasm-size-budget.json`. The internal crate remains `0.1.0`; the npm package version tracks the product.

## Native renderer

New crate `agent-spreadsheet-render`: umya worksheet → flat scene → tiny-skia → PNG, with subset Carlito Regular and Bold embedded, no system fonts, and identical pixels on native and wasm32. `screenshot_sheet` now defaults to the native backend wherever the `render` feature is compiled in (default on natively, always in WASM); LibreOffice stays available as `backend: "libreoffice"` where installed.

`screenshot_sheet` output gains additive fields: `renderer` (`native-raster/1` or `libreoffice`), `fidelity` (`full` | `partial`), `warnings` (closed enum: `conditional_format_omitted`, `chart_omitted`, `image_omitted`, `font_substituted`, `rich_text_flattened`, `number_format_approximated`, `formulas_unevaluated`, `text_rotation_omitted`, `pattern_fill_approximated`), `calculation`, `width`, `height`, and `png_level`. Input gains optional `backend` and `png_level` (`fast` | `balanced` | `best`). Rendering never recalculates; cached values are drawn and `formulas_unevaluated` says so.

CLI: `asp render book.xlsx --sheet Sheet1 --range A1:F40 --output sheet.png`. See `docs/RENDERING.md`.

Measured on the release binary: a 40-row by 13-column range renders in 5–21 ms natively and 41–86 ms in WASM; a 100-row by 30-column range in about 30 ms natively. Workbook parse, not rendering, dominates on large files.

## Known limitations

- Charts, images, conditional formatting, rich text runs, and rotated text are declared through warnings rather than drawn.
- Workbooks authored by openpyxl carry drawings that umya cannot see (default-namespaced roots, absolute relationship targets, charts in `oneCellAnchor`), so `chart_omitted` and `image_omitted` do not fire for them yet. Tracked as ticket 5007.
- The browser worker path is covered by unit tests over a message port; a real-browser lane is a follow-up.
- The brotli size gate has under one percent of headroom.

## Install or update

```bash
# Shell installer, pinned CLI (add --mcp to install the server too)
curl -fsSL https://raw.githubusercontent.com/PSU3D0/agent-spreadsheet/main/install.sh | ASP_VERSION=0.15.0 sh

# Prebuilt Cargo packages
cargo binstall --force agent-spreadsheet@0.15.0
cargo binstall --force agent-spreadsheet-mcp@0.15.0

# npm CLI, SDK, and WASM runtime
npm install --global agent-spreadsheet@0.15.0
npm install agent-spreadsheet-sdk@0.15.0 agent-spreadsheet-wasm@0.15.0

# Homebrew
brew update && brew upgrade psu3d0/tap/agent-spreadsheet

# Full MCP image
docker pull ghcr.io/psu3d0/agent-spreadsheet:0.15.0-full
```
